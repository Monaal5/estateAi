1. Introduction

estate AI is a full-stack web application that helps a commercial lender decide whether a property loan is safe to make. An AI engine reads loan data and documents (including scanned PDFs and photos), flags risks, answers questions through a Copilot, and writes the credit memorandum. All financial ratios — DSCR, LTV and Debt Yield — are calculated with fixed formulas in backend/app/finance.py; the AI never produces these numbers.

1.1 Purpose

This document defines the approach, scope, resources, schedule and the complete set of test cases needed to verify that estate AI meets its functional, financial-accuracy, security and quality requirements before release to credit officers and underwriters.

2.2 Out of Scope

  • Accuracy of the third-party AI model itself (only its integration, error handling and output use are tested).
  • User authentication / role-based access (not implemented in the current release — logged as a risk, see §13).
  • Mobile native apps; load testing beyond the stated AI free-tier rate limits.
  • Legacy prototype components in src/components, src/pages and server/ (Node) that are not wired to the current dashboard.

3.2 Test Types & Techniques

  • Equivalence partitioning & boundary value analysis — DSCR/LTV policy thresholds (1.25x, 75%), upload size limits (14 MB / 20 MB), rate & term normalisation (rate > 1, term ≤ 40).
  • Negative testing — unsupported file types, corrupt PDFs, unknown deal IDs, AI offline, DB offline, 429 rate limit.
  • "No fake data" verification — on any AI failure, the UI must show the real error plus Retry, never placeholder values.
  • Data-integrity testing — ratios on screen must match the calculation oracle in §10 exactly.
  • Exploratory sessions — 60-minute time-boxed charters per module.

10. Underwriting Formula Verification (Calculation Oracle)

Formulas: Annual debt service = monthly amortising payment(loan, rate, termMonths) × 12  |  DSCR = NOI ÷ (proposed + existing annual debt)  |  LTV = loan ÷ value × 100  |  Debt Yield = NOI ÷ loan × 100
Grading (policy 1.25x / 75%): Strong = DSCR ≥ 1.50 and LTV ≤ 65 · Adequate = DSCR ≥ 1.25 and LTV ≤ 75 · Marginal = DSCR ≥ 1.15 · Weak = otherwise
Normalisation: rate > 1 is treated as a percent (6.5 → 0.065); termMonths ≤ 40 is treated as years (25 → 300); "$" and "," stripped from numbers.

Expected values below were produced by executing finance.py directly and must match the UI and API exactly.
