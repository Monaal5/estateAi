4. Defects Raised

S1 CRITICAL  DEF-01 — Loan term used as amortization, so DSCR is wrong

Observed: PDF states "Loan Term 10 years (120 months) · Amortization 30 years (360 months)". financials.termMonths = 120, so debt service is $2,549,095 and DSCR 0.68x instead of $1,439,888 and 1.20x.

Root cause: the upload prompt in backend/app/main.py (line ~377) asks only for "termMonths":number and never says this means amortization. The deal-generation prompt (line 80) does define it as amortization, so the two prompts are inconsistent.

Impact: wrong grade, wrong memo recommendation, wrong Copilot answers. Any loan with a term shorter than its amortization (most CRE loans) is affected.

Suggested fix: define the field explicitly ("termMonths: AMORTIZATION period in months, NOT the loan maturity term"), or extract both loanTermMonths and amortizationMonths and use the latter in finance.py.

S2 HIGH  DEF-02 — Copilot cannot see uploaded documents

Observed: "What documents are still outstanding?" got the answer "rent roll and insurance". The rent roll was provided; the real outstanding items are tax returns, bank statements and KYC. "What is the tax reassessment risk?" got the answer "Unknown", even though the document extraction flagged it.

Root cause: the chat prompt (main.py lines 240–246) only includes DEAL, UNDERWRITING and MEMO. It does not include uploaded_documents (summary, fields, risk flags).

Suggested fix: add each document's summary, riskFlags and key fields to the Copilot context.

S2 HIGH  DEF-03 — Mixed deal identity after upload

Observed: the AI detected that borrower, sponsor, property and city all differ from the deal, but only the financials were applied. The memo now says "Apex Multifamily Holdings LLC … The Meridian at Brickell, Miami, FL" while using Harborview's (Austin) numbers.

Root cause: main.py lines 391–401 apply only financials. There is no check that the document belongs to the deal, and there is no way to create a new deal for a new client.

Suggested fix: warn or block when identity fields mismatch, and add a "New deal from document" intake flow so a new client can be onboarded.

S2 HIGH  DEF-04 — Underwriting workspace shows simulated sources, not the real document

Observed: the Extracted Facts panel cites "P&L Statement, FY2023", "Purchase Agreement, Exhibit B" and "Term Sheet, V2". None of these exist in the uploaded package.

Root cause: underwriting_prompt (main.py line 162) tells the AI to "simulate what document extraction found" and does not receive the uploaded documents. This contradicts the README's "No fake data" principle.

Suggested fix: when documents exist, build extractions from the stored extracted_data (real source and page); simulate only when no documents are uploaded, and label that clearly.

S3 MEDIUM  DEF-05 — Memo says package 100% complete although documents are outstanding

Observed: packageCompleteness = 100 while tax returns, bank statements and KYC are listed as outstanding in the client PDF.

Root cause: memo_prompt (line 172) receives no document data. Suggested fix: pass document checklists and risk flags into the memo prompt.

S3 MEDIUM  DEF-06 — Internal occupancy conflict not flagged

Observed: the application states 96% occupancy, while the certified rent roll shows 95.0% (114/120). Both values were extracted but no conflict was raised. Suggested fix: add an instruction to the extraction prompt to cross-check values within the document, not only against the deal.
